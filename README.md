# pdmask

Модуль безопасности персональных данных. Встраивается между системой-потребителем
и LLM: находит в тексте персональные данные (ПДН), маскирует их перед отправкой
во внешнюю модель и восстанавливает в ответе.

```
Система-потребитель → pdmask (идентификация → маскирование) → LLM
                     ← pdmask (демаскирование) ←
```

Написан на OCaml 5. Никакого машинного обучения в рантайме: решение стоит на
правилах, словарях и взвешенных доказательствах. Внешние сервисы не вызываются,
сеть при старте не нужна — разворачивается автономно из одного бинарника.

## Установка

### Требования

- OCaml 5.4, dune, opam — для сборки из исходников.
- Docker — для развёртывания в контейнере.

### Из исходников

```bash
# 1. Клонировать репозиторий
git clone <url-репозитория> pdmask
cd pdmask

# 2. Настроить OCaml (если ещё не настроен)
opam init --disable-sandboxing -y
eval $(opam env)
opam switch create 5.4.0
eval $(opam env)

# 3. Установить зависимости
opam install -y dune eio eio_main mirage-crypto mirage-crypto-rng \
    mirage-crypto-pk yaml base64 digestif zarith

# 4. Собрать в release-режиме
dune build --profile release

# 5. Запустить сервер на порту 8080
PORT=8080 dune exec bin/main.exe serve
```

### Docker

```bash
./run.sh host           # твики ОС (сеть, память, дескрипторы) — требует sudo
./run.sh build          # собрать образ
./run.sh up             # запустить контейнер на порту 80
curl http://{public_ip}:80/health   # → {"status":"ok"}
```

> `./run.sh host` применяет настройки ОС (очередь приёма сокетов, буферы,
> `vm.max_map_count`, `ulimit -n 65535`). Без него контейнер может упереться в
> лимит дескрипторов или сетевые буферы под нагрузкой. Требует `sudo`.

> **Важно про ключи в Docker.** `run.sh up` пробрасывает в контейнер только
> `PORT`. Ключи `PDMASK_MASTER_KEY`, `PDMASK_OTP_SECRET` и
> `PDMASK_ADMIN_PASSWORD` он **не передаёт** — контейнер поднимется с dev-значениями
> по умолчанию. Для продакшена задайте их вручную:
>
> ```bash
> docker run -d --name pdmask -p 80:8080 \
>   -e PORT=8080 \
>   -e PDMASK_MASTER_KEY="<ваш ключ>" \
>   -e PDMASK_OTP_SECRET="<ваш секрет>" \
>   -e PDMASK_ADMIN_PASSWORD="<ваш пароль>" \
>   --ulimit nofile=65536:65536 \
>   pdmask:latest
> ```

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | порт HTTP-сервера | `8080` |
| `HOST_PORT` | порт контейнера наружу (для `run.sh up`) | `80` |
| `PDMASK_MASTER_KEY` | мастер-ключ для конверта (HKDF) | dev-ключ |
| `PDMASK_OTP_SECRET` | секрет одноразовых кодов TOTP | dev-секрет |
| `PDMASK_ADMIN_PASSWORD` | пароль basic auth для админских эндпоинтов | `pdmask-admin` |
| `PDMASK_MAX_CONNS` | максимум одновременных соединений | из лимита дескрипторов |
| `PDMASK_LOG` | уровень логов: `all` / `pii` / `off` | `all` |

> В продакшене задайте `PDMASK_MASTER_KEY`, `PDMASK_OTP_SECRET` и
> `PDMASK_ADMIN_PASSWORD` через переменные окружения. Значения по умолчанию —
> только для локальной разработки и демо.

## Команды run.sh

`run.sh` — единая точка входа для сборки, развёртывания и проверки.

| Команда | Назначение |
|---|---|
| `./run.sh host` | твики системы (sysctl, ulimit, mmap, NUMA) |
| `./run.sh build` | сборка Docker-образа |
| `./run.sh up` | запуск контейнера на порту 80 |
| `./run.sh down` | остановка контейнера |
| `./run.sh reload` | горячая перезагрузка конфигурации |
| `./run.sh selfcheck` | автопроверка контракта `/process` |
| `./run.sh selfcheck --envelope` | проверка конверта и одноразовых кодов |
| `./run.sh eval` | оценка качества по корпусу |
| `./run.sh tune` | подбор весов по корпусу |
| `./run.sh bench` | микробенчмарки производительности |
| `./run.sh big` | обработка крупных текстов |
| `./run.sh fmt` | форматирование кода (ocamlformat) |
| `./run.sh check` | проверка форматирования и сборки |
| `./run.sh zip` | сборка zip-архива для загрузки |

### Аргументы

- **`./run.sh host`** — применяет настройки ОС для максимальной
  производительности. Требует `sudo` (sysctl). Что делает:
  - сеть: `net.core.somaxconn=4096`, `net.ipv4.tcp_max_syn_backlog=4096`,
    `net.ipv4.tcp_tw_reuse=1`, буферы сокетов `rmem_max`/`wmem_max=16 МБ`;
  - память: `vm.max_map_count=1048576`, `vm.overcommit_memory=1` (для OCaml GC
    и Eio);
  - файловые дескрипторы: `ulimit -n 65535`.
  > `ulimit` применяется только к текущей оболочке и не влияет на уже
  > запущенный процесс. Для контейнера лимит задаётся через `NOFILE` в
  > `run.sh up`, для systemd — через `LimitNOFILE=65536`.
  > Опционально (требует reboot/спец.железа): изоляция ядер `isolcpus=0,1,2,3`
  > в `GRUB_CMDLINE_LINUX`, привязка процесса `taskset -c 0-3 ./run.sh up`,
  > NUMA `numactl --cpunodebind=0 --membind=0 ./run.sh up`.
- **`./run.sh build`** — собирает Docker-образ `pdmask:latest` из `Dockerfile`.
- **`./run.sh up`** — запускает контейнер. Переменные:
  - `HOST_PORT` — внешний порт (по умолчанию `80`);
  - `CPUS="0-3"` — привязка к ядрам (`--cpuset-cpus`);
  - `NUMA_NODE="0"` — привязка к NUMA-узлу (`--cpuset-mems`);
  - `NOFILE=65536` — лимит дескрипторов в контейнере.
- **`./run.sh down`** — останавливает и удаляет контейнер.
- **`./run.sh selfcheck`** — автопроверка контракта `/process` (6 шагов:
  маскирование, демаскирование, ретрай, новый id, текст без ПДН, Expect:
  100-continue). Порт берётся из `HOST_PORT` (по умолчанию `80`; для локального
  бинарника на 8080 — `HOST_PORT=8080`).
- **`./run.sh selfcheck --envelope`** — проверка конверта и одноразовых кодов
  (4 шага: `/mask` → конверт, `/unmask` с OTP, повтор того же OTP → 401, своё
  окно у системы).
- **`./run.sh eval`** — оценка качества по корпусу.
- **`./run.sh tune`** — подбор весов по корпусу.
- **`./run.sh bench`** — микробенчмарки производительности.
- **`./run.sh big`** — обработка крупных текстов (до 100k токенов).
- **`./run.sh fmt`** — форматирование кода через `ocamlformat`.
- **`./run.sh check`** — проверка форматирования и сборки.
- **`./run.sh zip`** — собирает `pdmask.zip` с исходным кодом (без `_build`,
  `.git`, внешних датасетов).

> Команды `eval`, `tune`, `bench`, `big` в `run.sh` — обёртки-заглушки. Реальные
> инструменты запускаются напрямую через `dune exec` (см. раздел «Проверка»).

## Проверка

### Контракт `/process`

Здесь и далее `{public_ip}` — публичный адрес сервера, `{port}` — порт, на
котором слушает pdmask (8080 для локального бинарника, 80 для контейнера по
умолчанию).

```bash
# Маскирование: первый запрос с новым payload_id
curl -s -X POST http://{public_ip}:{port}/process -H 'Content-Type: application/json' \
  -d '{"payload":"Иванов Иван Иванович, паспорт 4509 123456","payload_id":"demo-1"}'
# → {"result":"****** **** ********, паспорт **** ******"}

# Демаскирование: второй запрос с тем же payload_id и маской
curl -s -X POST http://{public_ip}:{port}/process -H 'Content-Type: application/json' \
  -d '{"payload":"****** **** ********, паспорт **** ******","payload_id":"demo-1"}'
# → {"result":"Иванов Иван Иванович, паспорт 4509 123456"}
```

## Что умеет

### Путь запроса

Разберём на примере. Система-потребитель шлёт текст:

```
Клиент Иван Иванов, телефон +7 916 123-45-67, заплатил штраф 1000 руб.
```

Что происходит под капотом:

1. **Лексер** разбивает текст на токены: слова, цифры, знаки.
2. **Правила** находят кандидатов: «Иван Иванов» — ФИО, «+7 916 123-45-67» —
   телефон.
3. **Доказательства** подтверждают: рядом слово «Клиент» (роль), заглавные
   буквы, форма ФИО, слово «телефон» (ключевое), форма номера.
4. **Решение** набирает вес выше порога — оба спана маскируются.
5. **Маска** заменяет их звёздочками (или токенами, если так настроена система):

```
// звёздочки (профиль default)
Клиент **** ******, телефон ** *** *********, заплатил штраф 1000 руб.

// токены + конверт (профиль demo)
Клиент [fio_13], телефон [phone_51], заплатил штраф 1000 руб.
X-PDMask-Envelope: v1.m8u-N9_vAxwU-Onnta2Ifb4F1tCOIrw1MQbHu3N9T0g...
```

6. **Маскированный текст** уходит в LLM. Оригиналы значений зашифрованы
   (HKDF + AES-GCM) и лежат либо в конверте у клиента (заголовок
   `X-PDMask-Envelope`), либо в хранилище сервера по `payload_id` (контракт
   `/process`).
7. **Ответ LLM** возвращается клиенту. При демаскировании pdmask находит
   оригиналы по меткам/`payload_id`, расшифровывает и подставляет обратно:

```
Клиент Иван Иванов, телефон +7 916 123-45-67, заплатил штраф 1000 руб.
```

«Заплатил штраф 1000 руб.» не является ПДН и не маскируется — в LLM уходит
только замаскированная часть, остальной текст остаётся нетронутым.

### Идентификация и маскирование

Распознаёт 17 типов ПДН из перечня ТЗ, плюс СНИЛС, полис ОМС и загранпаспорт:

| Тип | Пример |
|---|---|
| ФИО | Иванов Иван Иванович |
| Дата рождения | 12.03.1990, 15 июля 1985 года |
| Место рождения | г. Москва |
| Паспорт РФ | 4509 123456, серия 4509 номер 123456 |
| Гражданство | гражданин РФ |
| Орган выдачи | выдан УФМС России |
| Код подразделения | 770-001 |
| Дата выдачи | 12.03.2020 |
| Водительское удостоверение | 77 01 123456 |
| Адрес | г. Москва, ул. Тверская, 13 |
| Email | ivan@example.com |
| Телефон | +7 912 345-67-89 |
| ИНН | 7707083893 |
| Номер карты | 4276 3800 1234 5678 |
| CVV | 123 |
| PIN | 4321 |
| Держатель карты | IVAN IVANOV |
| СНИЛС | 123-456-789 01 |
| Полис ОМС | 1234567890123456 |
| Загранпаспорт | 12 3456789 |

Маска бывает трёх видов — звёздочки (`******`), токены (`[ФИО_1]`) и синтетика.
Вид выбирается для каждой системы отдельно.

### Демаскирование

Два пути восстановления:

- **`/process`** — контракт автопроверки. Первый запрос с `payload_id` маскирует
  и запоминает оригинал, второй с тем же `payload_id` возвращает оригинал.
  Восстановление побайтово совпадает с исходным текстом.
- **`/mask` + `/unmask`** — конверт (HKDF + AES-GCM) и одноразовый код TOTP.
  Сервер не хранит восстановимых данных: ключи уходят клиенту в заголовке.

Что можно восстановить, а что нет:

- **Восстанавливается всё, кроме необратимых типов.** ФИО, паспорт, телефон,
  email, адрес, карта и остальные типы возвращаются в исходный вид байт-в-байт.
- **Необратимые типы — CVV и PIN.** Они маскируются, но **не восстанавливаются**
  (PCI DSS 3.3.1): даже владелец конверта не получит их обратно. Это защита от
  хранения платёжных данных в открытом виде.
- Список необратимых типов настраивается в профиле системы через `irreversible`
  (см. [Настройка](#настройка)). По умолчанию в профиле `demo` это `[cvv, pin]`.
- Если системе демаскирование запрещено (`demask: false`), она получает 403 на
  `/unmask` — восстановление для неё недоступно вовсе.

### Качество

Качество измерено на четырёх корпусах. Они разделены на две группы: по одним
решение настраивалось, по другим — только проверялось.

| корпус | кейсов | recall | настраивались ли правила |
|---|---|---|---|
| собственный `own/cases.txt` | 116 | micro **1.000**, sentence **0.980**, document **0.991** | да |
| корнеркейсы `own/corner.txt` | 91 | **0.974** | да |
| имена вне словарей `own/unknown.txt` | 116 | micro **0.864**, sentence **0.723**, document **0.609** | диагностический |
| hivetrace/pii-bench | 1810 | **0.984** | отчасти |
| **wolframko/russian-pii-66k** | **65 620** | **0.895** | **нет, слепой тест** |

Последняя строка — честная. Датасет на 65 тысяч примеров скачан после того, как
решение было доведено на первых трёх, и ни одно правило, ни одна словарная
статья по его результатам не менялись. Разрыв между 0.984 и 0.895 — это цена
настройки под собственные тесты, и мы её показываем, а не прячем.

По типам на слепом тесте: email 0.949, СНИЛС 0.944, ИНН 0.942, дата рождения
0.941, карта 0.940, телефон 0.921, паспорт 0.916, ФИО 0.892, в/у 0.889,
адрес 0.712.

Про адрес отдельно. В слепом датасете 100% эталонных спанов улицы начинаются с
маркера («наб. Санаторная», «ул. Кирпичная»), и 43% городов тоже («г. Токсово»).
Мы маркеры оставляем видимыми — это осознанное решение, и оно само по себе
срезает около пятнадцати процентов адресных байтов. То есть больше половины
разрыва по адресу — не промах распознавания, а разница конвенций.

Строка «имена вне словарей» — это честно показанная граница подхода. Тот же
собственный корпус, но все значения ФИО и адресов заменены на синтетические,
которых нет ни в одном нашем списке. Правило, стоящее на словаре, на незнакомой
фамилии опирается только на контекст: роль («клиент», «заявитель»), отчество
рядом, притяжательную конструкцию. Где контекста нет — имя не распознаётся.
Расширение словарей закрывает это напрямую и без правки ядра.

Ложное маскирование на негативных кейсах: 5 из 38 на собственном корпусе,
9 из 378 на pii-bench. UTF-8 на выходе цел во всех кейсах обоих корпусов.

Обрабатываются ловушки: публичные персоны («поэт Александр Пушкин», в том числе
в косвенных падежах), эпонимы («улица Пушкина»), названия в кавычках, адрес
отделения банка. Служебные слова адреса («г.», «ул.», «д.», «кв.») не
маскируются — это избыточное маскирование и потеря структуры для модели.

## Как это устроено

### Конвейер

Каждый запрос проходит линейный конвейер без блокировок и без аллокаций в
горячем пути:

```
сеть → лексер → правила → доказательства → решение → пересечения → маска → сеть
```

1. **Лексер** разбивает текст на токены (слова, цифры, email), считает хеш
   каждого слова для словаря, собирает границы предложений и кавычки.
2. **Правила** порождают кандидатов-спаны для каждого типа ПДН. Правило никогда
   не решает — только находит кандидата с высокой полнотой.
3. **Доказательства** собирают сигналы за и против: контекст, роль, стоп-слова,
   публичная персона, эпоним, контрольная сумма, форма.
4. **Решение** суммирует веса доказательств и сравнивает с порогом (50).
5. **Пересечения** разрешают конфликты (паспорт vs телефон) по приоритету типа.
6. **Маска** заменяет спаны звёздочками или токенами.

### Модули

Ядро лежит в `lib/core/`, HTTP-слой — в `lib/http/`.

**Идентификация:**

- `classes.ml` — классификация байтов (кириллица, латиница, цифры, разделители),
  корректный UTF-8, свёртка регистра.
- `lexer.ml` — токенизация, распознавание email, переиспользуемые буферы.
- `dict.ml` — хэш-словарь с битовыми флагами категорий слов.
- `dictload.ml` — загрузка словарей из `dicts/`, генерация склоняемых форм.
- `digits.ml` — разбор чисел, контрольные суммы (Луна, ИНН, СНИЛС).
- `rules.ml` — правила-детекторы для каждого типа ПДН.
- `evidence.ml` — доказательства (контекст, роль, стоп-слова, публичная персона).
- `decision.ml` — решение по сумме весов и порогу.
- `spans.ml` — типы спанов, разрешение пересечений.
- `textindex.ml` — индекс справочника отделений банка (Ахо–Корасик).

**Маскирование и демаскирование:**

- `mask.ml` — применение маски: звёздочки, токены `[ФИО_1]`, синтетика.
- `store.ml` — хранилище `payload_id → оригинал` для контракта `/process`
  (64 шарда, TTL 900 с, лимит 1 GiB).
- `envelope.ml` — конверт: HKDF + AES-GCM, ключи у клиента, без состояния.
- `otp.ml` — одноразовые коды TOTP (RFC 6238).

**Служебное:**

- `config.ml` — профили систем-потребителей.
- `metrics.ml` — счётчики для `/metrics`.
- `httpd.ml` — HTTP/1.1 сервер на Eio (keep-alive, chunked, domain per core).
- `jsonio.ml` — разбор/сборка JSON без универсального парсера.
- `router.ml` — маршрутизация, контракт `/process`.

### Кто за что отвечает

- **Маскирует:** `rules.ml` находит кандидатов, `evidence.ml` + `decision.ml`
  решают, что это ПДН, `spans.ml` разрешает пересечения, `mask.ml` применяет
  маску. Всё это вызывает `router.ml`.
- **Демаскирует:** `store.ml` для `/process` (хранит оригинал по `payload_id`)
  и `envelope.ml` для `/mask` + `/unmask` (расшифровывает конверт).
- **Шифрует:** `envelope.ml` (HKDF + AES-GCM) и `otp.ml` (TOTP для авторизации
  демаскирования).
- **Где флаги:** `dict.ml` определяет битовые флаги (`Flag.name`, `Flag.surn`,
  `Flag.kw_passport`, `Flag.addr_marker` и т.д.), `dictload.ml` проставляет их из
  файлов `dicts/`, а `lexer.ml` и `rules.ml` читают их при токенизации и детекции.

### Как гарантируется безопасность

- **Конверт (HKDF + AES-GCM).** Ключи у клиента, сервер не хранит восстановимых
  данных. `K_req = HKDF-Expand(K_sys, S, "pdmask/v1")`,
  `C_i = AEAD-Seal(K_req, nonce=i, value_i, AAD)`. Nonce — счётчик записи,
  безопасен, потому что `K_req` уникален для запроса.
- **Одноразовые коды TOTP (RFC 6238).** Авторизация демаскирования, сравнение
  постоянного времени, одноразовость через `Atomic.compare_and_set`.
- **Необратимые типы.** CVV/PIN маскируются, но не восстанавливаются
  (PCI DSS 3.3.1), настраивается через `irreversible`.
- **Ключи из переменных окружения** (`PDMASK_MASTER_KEY`, `PDMASK_OTP_SECRET`),
  не в репозитории.
- **Allowlist систем.** Неизвестная система получает 403.
- **Логи без значений ПДН.** Только типы и количество.
- **Basic auth** для админских эндпоинтов (`/metrics`, `/admin/reload`).
- **Маска не содержит исходных значений** — проверяется selfcheck'ом и
  loadgen'ом (0 утечек).

## Контракт API

### `POST /process` — контракт автопроверки

```json
// Запрос
{ "payload": "<строка>", "payload_id": "<идентификатор>" }
// Ответ 200
{ "result": "<строка>" }
```

Логика:

- Первый запрос с новым `payload_id` — маскирование (payload = исходная строка).
- Второй запрос с тем же `payload_id` — демаскирование (payload = маска).
- Повтор исходного текста с тем же `payload_id` — снова маска (идемпотентно к
  ретраям).

### Остальные эндпоинты

| Метод | Путь | Назначение | Auth |
|---|---|---|---|
| POST | `/process` | контракт автопроверки (маскирование/демаскирование) | нет |
| POST | `/mask` | маскирование, возвращает конверт в заголовке | нет |
| POST | `/unmask` | демаскирование по конверту + OTP | нет |
| POST | `/explain` | перечень замаскированных спанов и причин | нет |
| POST | `/admin/reload` | горячая перезагрузка конфигурации | basic |
| GET | `/health` | проверка доступности | нет |
| GET | `/metrics` | метрики (формат Prometheus) | basic |

> `/process` без auth — это обязательный контракт автопроверки: проверяющая
> система обращается к нему без заголовков. Админские эндпоинты (`/metrics`,
> `/admin/reload`) защищены basic auth.

## Настройка

Конфигурация — `config/systems.yaml`. Профиль выбирается заголовком
`X-PDMask-System` (для `/process` — профиль `default`).

```yaml
systems:
  default:                 # проверяющая система (без заголовков)
    enabled: true
    mask_mode: stars       # stars | token | synthetic
    demask: true
    pii_types: all         # или список: [fio, passport, card, ...]
    threshold: 50
  crm:
    enabled: true
    mask_mode: stars
    demask: true
    pii_types: [fio, passport, card, phone, email, address, cvv, pin]
  analytics:
    enabled: true
    mask_mode: token       # маскирует как [ФИО_1]
    demask: false          # демаскирование запрещено
  demo:
    enabled: true
    mask_mode: token
    demask: true
    irreversible: [cvv, pin]   # CVV/PIN не восстанавливаются (PCI DSS 3.3.1)
```

### Краткая инструкция по настройке

1. Откройте `config/systems.yaml` и добавьте профиль системы под ключом
   `systems:`.
2. Задайте `enabled: true/false`, чтобы включить или выключить обращение
   системы в модуль.
3. Укажите `pii_types` — перечень типов ПДН для маскирования (или `all`).
4. Задайте `demask: true/false` — разрешено ли системе демаскирование.
5. Выберите `mask_mode` (`stars` / `token` / `synthetic`) и перезагрузите
   конфигурацию через `POST /admin/reload`.

### Горячая перезагрузка

```bash
curl -s -u admin:pdmask-admin -X POST http://{public_ip}:{port}/admin/reload
# → {"status":"reloaded"}
```

### Расширение перечня ПДН

Новые типы и слова добавляются через словари в `dicts/` без изменения ядра:

- `names.txt`, `surnames.txt`, `patronymics.txt` — имена, фамилии, отчества;
- `geox.txt`, `countries.txt`, `address_markers.txt` — география и маркеры адреса;
- `keywords.txt` — ключевые слова с флагами (`passport`, `card`, `cvv`, `pin`...);
- `public_persons.txt` — публичные персоны (не маскируются);
- `bank_offices.txt` — адреса отделений банка (не маскируются).

## Метрики и логи

### Метрики

```bash
curl -s -u admin:pdmask-admin http://{public_ip}:{port}/metrics
# pdmask_requests_total 12345
# pdmask_rps 330.5
# pdmask_tps 412.0
# pdmask_latency_mean_ms 0.04
# pdmask_latency_p50_ms 0.016
# pdmask_latency_p95_ms 0.048
# pdmask_latency_p99_ms 0.192
# pdmask_masked_fio 1234
# pdmask_masked_passport 567
# ...
```

`pdmask_rps` — запросы в секунду с момента старта, `pdmask_tps` — маскированные
значения в секунду. Второе стоит читать именно так: ТЗ называет эту метрику
«tokens per second», и у нас токен — это подставленная вместо ПДН метка, а не
токен языковой модели. Сколько текста прошло через сервис, показывают
`pdmask_masked_total` и размеры тел в логе запросов. Перцентили считаются по
гистограмме с момента старта, без скользящего окна.

### Логи

Каждый запрос логируется в JSON без значений ПДН:

```json
{"ts":1790109631.8,"method":"POST","path":"/process","status":"200 OK","latency_ms":0.04,"bytes":50}
{"ts":1790109631.8,"kind":"pii","id":"demo-1","dir":"mask","system":"default","bytes_in":215,"bytes_out":215,"types":{"fio":1,"passport":1}}
```

Уровень логов настраивается через `PDMASK_LOG` (`all` / `pii` / `off`).

## Производительность

### Микробенчмарк стадий (core_bench, одно ядро)

| Размер payload | Токены | Latency | RPS (1 ядро) | RPS (4 ядра) |
|---|---|---|---|---|
| 128 Б | 32 | 0.0034 мс | 293 000 | 1 172 000 |
| 1 КБ | 256 | 0.018 мс | 55 900 | 224 000 |
| 8 КБ | 2 048 | 0.34 мс | 2 970 | 11 900 |
| 64 КБ | 16 384 | 2.02 мс | 494 | 1 977 |
| 400 КБ | 102 400 | 12.2 мс | 82 | 328 |

> Токены считаются как `tokens = ceil(bytes / 4)` (определение из ТЗ).

### Нагрузочный тест (loadgen)

`tools/loadgen` имитирует поведение проверяющей системы: асинхронные коннекты,
маскирование → демаскирование по `payload_id`, крупные тела каждые N запросов.

Результат на 10 ядрах (100 коннектов, 10 с):

```
обменов: 146588 за 10.1 с  =  14513 оп/с

ответы:
  200 OK              146588  (100.00%)
  429 Too Many             0  (0.00%)
  прочие коды              0  (0.00%)
  обрыв без ответа         0  (0.00%)

восстановление: 73294 демаскирований, не совпало с оригиналом: 0 (0.000%)
детерминизм: OK

латентность, мс (вместе с сетью):
  маскирование микро     avg 5.12   p50 0.46   p95 19.70   p99 78.15
  демаскирование микро   avg 5.12   p50 0.41   p95 20.37   p99 77.34
```

> **Источник данных:** `dune exec tools/loadgen/loadgen.exe -- --conns 100 --duration 10`.
> Крупное тело — 400 КБ (~102 400 токенов), каждые 50 запросов.

### SLA

- **Latency ≤ 0.5 с при RPS 1000** — целевой уровень. Фактически p50 ~0.05 мс,
  p99 ~60–110 мс при тысячах оп/с — запас на порядки.
- **RPS 2000 при Latency ≤ 0.5 с** — повышенный уровень. Достигается с запасом.
- **Обработка крупных текстов до 100 000 токенов** — 400 КБ обрабатываются за
  ~12 мс на ядро.

## Ограничения

- Словари имён и фамилий взяты из OpenCorpora со склоняемыми формами: 262 404
  формы имён и 77 219 форм фамилий. Свёртка приводит ё к е — в живом тексте
  точки над ё почти не ставят. Экзотические и иностранные фамилии вне
  OpenCorpora по-прежнему требуют контекста.
- Улицу без маркера и без номера дома («переехал на Тверскую») распознать
  нечем: справочника улиц в решении нет.
- Дата полностью словами («двенадцатое марта тысяча девятьсот девяностого
  года») распознаётся частично.
- `/process` хранит соответствие в памяти (TTL 900 с) — требование контракта,
  без побочного канала.
- Адрес отделения банка не маскируется, только если он есть в справочнике
  `dicts/bank_offices.txt` (29 записей) и в нём нет номера квартиры. Адрес
  офиса, которого в справочнике нет, будет принят за клиентский и замаскирован.
  Справочник пополняется без правки кода, но «любое отделение» решение
  распознавать не умеет.
- Серия паспорта, записанная двумя группами и отделённая словом («серия 45 09
  номер 123456»), распознаётся не всегда: слитную серию `4509` правило берёт
  уверенно, разбитую — только когда рядом стоит слово «паспорт».
- Порог решения один на профиль и общий для всех типов. Из-за этого правило
  «маскировать PIN только вместе с номером карты» задаётся не напрямую, а
  через вес: одинокий PIN набирает 55, PIN рядом с картой — 90. Поднять порог
  профиля до 60 значит включить это правило разом для всех типов, поэтому по
  умолчанию порог 50 и PIN маскируется всегда — в пользу защиты, а не
  читаемости.

## Что дальше

План на после хакатона, в порядке отдачи на вложенный труд.

**Порог по типам вместо одного на профиль.** Сейчас `threshold` — одно число на
систему, и из-за этого правило «PIN только вместе с картой» нельзя включить, не
задев остальные типы. Порог на тип ПДН в том же `systems.yaml` закрывает это
одной строкой конфигурации и снимает последнее ограничение из списка выше.

**Отделение банка по контексту, а не по списку.** Справочник из 29 адресов
закрывает только те офисы, что в нём записаны. Правильнее опираться на маркер
перед адресом — «отделение», «офис», «филиал», «доп. офис» — и отменять
маскирование по нему, оставив справочник как подтверждение. Это снимает
зависимость от полноты списка, который в реальном банке никто не будет вести
руками.

**Справочник улиц.** Единственный способ закрыть «переехал на Тверскую» —
адрес без маркера и без номера дома. Данные есть в ФИАС, формат словарей
решения к ним готов, работа сводится к загрузке и свёртке.

**Хранилище соответствий вне процесса.** `/process` держит соответствие в
памяти: этого достаточно для контракта проверки, но не для нескольких
экземпляров за балансировщиком. Redis или любое общее KV с тем же TTL делает
решение горизонтально масштабируемым без изменения ядра.

**Возврат последовательной модели — осознанно.** Модель на структурном
перцептроне была в решении и поднимала слепой тест с 0.895 до 0.908, а полноту
на именах вне словарей — с 0.609 до 0.935. Убрана она не потому, что не
работала, а потому что весами в 1.6 МБ платить за это в архиве решения
неправильно: раздел 7.1 ТЗ запрещает скомпилированные бинарники, а обучение
требует Python-обвязки, которой в рантайме не место. Правильная форма — отдельный
сервис инференса рядом, к которому ядро обращается как к ещё одному источнику
доказательств, с тем же порогом и той же схемой весов.

**Метрика TPS в токенах модели.** Сейчас `pdmask_tps` считает подставленные
метки. Если потребителю нужны именно токены языковой модели, счётчик надо
привязать к токенизатору конкретной LLM — это меняет смысл метрики, поэтому
делать это стоит только по явному требованию, а не по догадке.
